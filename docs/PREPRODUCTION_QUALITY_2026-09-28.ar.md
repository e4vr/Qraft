# مراجعة جودة Qraft قبل الإنتاج — 28 سبتمبر 2026

## النطاق

إصلاح الربط بين الواجهة والخادم، توحيد النصوص التي يكتبها التطبيق بالإنجليزية، وتحسين التفاعلات الحالية. لم تُضف أو تُحذف ميزة، ولم تتغير الخطط أو الصلاحيات أو قواعد المراجعة. احتُفظ بالتعديلات السابقة الموجودة في مساحة العمل. لم تُنفذ عملية نشر أو تعديل لبيانات الإنتاج.

## خريطة المراجعة

| المسار الحالي | الربط الذي تمت مراجعته |
| --- | --- |
| الدخول والحساب | `auth-client` ← `api-client` ← router / auth service، ورسائل الشبكة وMFA |
| البنوك والمساهمات | collaboration / question-edit / classification / import، مع حفظ حدود البنك والصلاحيات |
| الاختبارات والتقدم | state checkpoints وReady Tests، وتغطية الانقطاع وإعادة الإرسال والخصوصية بالاختبارات الحالية |
| الدعم | `ContactWorkspace` ← `/contact` ← tickets / ticket_messages |
| الاشتراكات | plan-catalog / quote / checkout، وحالة الخطة والسعر ورمز الخصم |
| الإدارة والمراجعة | reviewer search / review history / import monitor وأزرار النسخ ورسائل النتائج |
| العرض | التنقل، النوافذ، حالات التحميل، عرض الهاتف، ورسائل النجاح والخطأ |

## الإصلاحات

| المشكلة | المعالجة |
| --- | --- |
| إعادة إرسال رسالة الدعم كانت تعيد استجابة مختلفة عن الإرسال الأول | يعيد الخادم التذكرة والرسالة المحفوظتين، دون رسالة إضافية، حتى لو تغيرت حالة التذكرة بعد نجاح الرد الأصلي |
| إمكانية استخدام معرّف طلب قديم مع رسالة أو تذكرة مختلفة | رفض إعادة الاستخدام المتعارض مع إبقاء إعادة المحاولة المطابقة صالحة |
| مشاركة تحميل التذاكر وإرسالها لحالة انتظار واحدة | فصل الحالتين وإضافة حارس يمنع إرسالين متزامنين، وتعطيل التحرير والتنقل المتعارض أثناء الإرسال |
| اختلاط مسودة إنشاء تذكرة بالرد على تذكرة أخرى | حفظ مسودة مستقلة لكل سياق داخل شاشة الدعم واستعادتها عند الرجوع؛ لا يُدّعى أنها محفوظة بعد إغلاق الصفحة |
| تحديث قائمة الدعم محليًا دون احترام البحث والصفحات | إعادة قراءة المورد المتأثر بعد الإقرار، بما يشمل إعادة المحاولة التي لم يصل إقرارها الأول |
| بقاء سعر خطة سابقة أثناء تغيير الخطة أو وصول استجابة قديمة | إظهار السعر المطابق للخطة الحالية فقط، وإهمال الاستجابات المتجاوزة، وتعطيل التأكيد حتى توفر سعر صالح |
| إعادة توليد معرّف checkout بعد فشل مبهم | الاحتفاظ بمعرّف العملية عند إعادة المحاولة؛ يتغير عند اختيار خطة أو تطبيق رمز جديد |
| فشل صامت في تغيير رمز الاختبار والبلاغ والإخفاء ولوحة النتائج | معالجة موحدة للأخطاء والانتظار ومنع تداخل العمليات، مع فصل رسالة النجاح عن الخطأ |
| استجابة بحث قديمة قد تستبدل نتائج مراقبة الاستيراد الجديدة | اعتماد أحدث طلب فقط، وإلغاء أثر الطلبات السابقة عند تغير البحث أو إغلاق التفاصيل |
| التداخل بين بحث المراجعين وإضافة مراجع | فصل التحميل عن الإضافة، وتعطيل الاختيار أثناء الانتظار، وعدم عرض «لا توجد نتائج» عند فشل البحث |
| رسائل عربية/إنجليزية مختلطة | توحيد النصوص المكتوبة داخل الواجهة والخادم بالإنجليزية، ومنها الدعم والاستيراد والاشتراكات والتأكيدات |
| تأكيد حذف المجلد بالعربية | تعرض الواجهة وتقبل الخادم `DELETE`؛ يحتفظ الخادم بقبول التأكيد القديم للتوافق مع واجهة قديمة مفتوحة |
| ادعاء عام بحفظ التغييرات محليًا عند استجابة غير مقروءة | رسالة محايدة قابلة للتصرف، مع الاحتفاظ بحالة HTTP وRetry-After وعدم اعتبار JSON المبتور نجاحًا |
| تعذر النسخ دون تغذية راجعة | رسائل واضحة عند فشل نسخ رابط البنك أو مفتاح MFA أو بصمة ملف الاستيراد |
| خروج نافذة مقارنة الخطط عن عرض الهاتف | تقييد عرض محتويات النافذة، وتمرير الجدول داخل حاويته، وإتاحة تمرير النوافذ الطويلة، وتكبير مساحة زر الإغلاق |
| علامات توفر ميزات الخطط غير مفهومة لقارئ الشاشة | إضافة Included / Not included إلى العلامات المرئية |
| تخزين ملفات التطوير المتغيرة بعناوين ثابتة بواسطة Service Worker | تسجيل العامل في نسخة الإنتاج فقط، وتجاوز ملفات Vite وملفات المصدر إذا بقي عامل سابق يتحكم بالصفحة؛ تبقى استراتيجية تخزين ملفات الإنتاج واختبارها |

نصوص المستخدمين والأسئلة والمحتوى المستورد لم تُترجم. التغييرات اللغوية تخص النصوص التي يملكها التطبيق.

## التحقق

- خط الأساس: 199 اختبارًا ناجحًا قبل هذه الحزمة.
- الاختبارات بعد الإصلاح: 202 اختبارًا ناجحًا، بما فيها اختبارات جديدة لعقد إعادة إرسال الدعم ورسائل الشبكة والاستجابة المبتورة والإلغاء وRetry-After.
- تحديث الاختبارات النصية التي كانت تتوقع التسميات العربية القديمة، مع الحفاظ على اختبار رفض تأكيد الحذف غير الصحيح.
- فحص TypeScript والتحليل البرمجي والبناء والتحقق التجريبي من إعدادات Cloudflare للإنتاج وstaging.
- نجحت اختبارات قاعدة البيانات Python الإحدى عشرة، ونجحت الاختبارات المركزة الثلاثة بعد آخر تعديل للواجهة والتخزين المؤقت؛ لا توجد أخطاء في فحص فروق الملفات.
- اختبارات API تعمل على قواعد D1 مؤقتة مستقلة؛ وتشمل مجموعة المشروع سيناريو 100 مستخدم اصطناعي، وعزل الحالات الشخصية، وإعادة الإرسال، وتزامن الإجابات.
- تحقق تفاعلي محلي بحساب QA اصطناعي: الدخول، خطأ انقطاع الاتصال، إرسال تذكرة، تعطيل الأزرار أثناء الإرسال، استعادة مسودة عند الرجوع، تبديل الخطة، رفض رمز خصم غير صالح، واستعادة سعر صالح دون تنفيذ اشتراك.
- مراجعة مرئية لنافذة مقارنة الخطط على عرض 390×844 وعرض 1440×1000. عرض الصفحة يساوي عرض الشاشة، وعرض محتوى النافذة لا يتجاوز عرضها في الحالتين. على الهاتف تم التحقق من تمرير الجدول إلى آخر الأعمدة (383px)، وزر الإغلاق 44×44. القياسات في `outputs/preproduction-visual-metrics.json` والصور في `outputs/preproduction-mobile.png` و`outputs/preproduction-mobile-scrolled.png` و`outputs/preproduction-desktop.png`.
- بعد تعديل Service Worker أُعيد اختبار تجاوز ملفات التطوير، مع التأكد من استمرار تخزين ملفات الإنتاج وتجاوز API. سجل الاختبارات المركزة النهائي: `outputs/preproduction-final-focused.log`.

أدلة التشغيل المحلية: `outputs/preproduction-baseline-tests.log`، `outputs/preproduction-final-tests.log`، `outputs/preproduction-cloudflare-check.log`. حساب QA وبياناته اصطناعية داخل قاعدة التطوير المحلية فقط.

## حدود النتيجة

هذه حزمة إصلاح محلية وليست إعلانًا بجهوزية نشر الإنتاج. مساحة العمل تحتوي تعديلات سابقة ولم تُحوّل إلى إصدار نظيف ملتزم. لم يُنفذ اختبار حي على staging أو اختبار Safari/iPhone فعلي. تبقى تحذيرات حجم بعض حزم JavaScript وتصنيف بعض المسارات من أداة البناء؛ لم تُخفَ التحذيرات أو تُغيّر الميزات لمعالجتها.

ظهر خطأ React في معاينة localhost ذات الملفات المخزنة سابقًا، بينما عملت معاينة نظيفة على 127.0.0.1 وسجّلت الدخول وعرضت التعديلات. كُشف أن العامل السابق كان يخزن ملفات Vite ومصدر الواجهة؛ أُصلح هذا السلوك. لم يُمسح مخزن متصفح المستخدم أو بياناته. قد تحتاج تبويبات التطوير القديمة إلى تحديث العامل وإعادة تحميل الصفحة؛ التحقق البصري النهائي أعلاه تم على المعاينة النظيفة. أُوقفت معاينة التطوير قبل البناء النهائي.
