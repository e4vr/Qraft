# جاهزية Qraft لخدمة SaaS — 27 سبتمبر 2026

هذه نسخة تحسين للأمان والتزامن وقابلية التشغيل فوق البنية الحالية: Workers + D1 + R2 + Durable Objects. لا تمثل شهادة جاهزية إنتاج أو ضمان خلو كامل من الأخطاء. يبقى [دستور المشروع](../QRAFT_ENGINEERING_CONSTITUTION.md) مرجع القرارات.

## نطاق المنتج المحفوظ

| المسار / المجال | العقد المحفوظ |
| --- | --- |
| الحساب والموافقة على التسجيل | الحسابات والصلاحيات وMFA للمسؤول وحظر الحسابات |
| QBanks والمساهمة والمراجعة | البنوك العامة والخاصة وعزل الصلاحيات والمراجعة والاستيراد وكشف التكرار |
| الاختبارات الشخصية والتقدم | التنقل المحلي، الملاحظات، العلامات، سجل الإجابات، الحفظ المحلي والمزامنة |
| Ready Tests | مشاركة الأعضاء والضيوف والتصحيح في الخادم وخصوصية المحاولات |
| البطاقات والهدف اليومي | الوظائف وحدود الباقات الحالية كما هي |
| الاشتراكات | طلب اشتراك ثم تفعيل المسؤول؛ إبقاء الدفع اليدوي قرار صريح من المستخدم |
| الدعم والإدارة | التذاكر الخاصة وسجل التدقيق والمراقبة وإدارة المستخدمين |
| PWA والمزامنة | نفس الشاشات وتدفق التنقل ودعم الاتصال المتقطع |

لم تُغيّر الأسعار أو تُحذف مزايا أو يُنقل المشروع إلى مزوّد آخر. لا توجد ترحيلات D1 جديدة في هذه الدفعة؛ آخر ترحيل قائم هو 0026. إصدار PWA أصبح **v4.6.2** لتمييز الشيفرة الجديدة.

## الإصلاحات الفعلية

1. **حدود الطلبات بحسب الحساب الموثّق:** المستخدمون المسجّلون على شبكة مشتركة لم يعودوا يشتركون في حد القراءة والكتابة. الحساب لا يُستنتج من قيمة cookie أو معرف يرسله العميل؛ يُتحقق منه في الخادم. تبقى محاولات المصادقة محمية بعنوان الشبكة، وحدها الحالي 20 محاولة/دقيقة؛ اختبار التزامن يستخدم جلسات منشأة مسبقًا ولا يختبر دخول 100 حساب من IP واحد خلال دقيقة.
2. **إحصاءات الإجابات المتزامنة:** يرسل العميل إجابة صاحب الحساب فقط؛ ويدمج الخادم هذه الإجابة داخل عملية SQL واحدة بدل استبدال خريطة إجابات الجميع. يحافظ على إجابات المستخدمين الآخرين ويرفض محاولة تعديلها. إعادة الإجابة المحفوظة نفسها لا تنشئ كتابة جديدة عبر هذا المسار.
3. **ربط العمليات المعلقة بالحساب:** تحمل عمليات حالة المستخدم والتعاون معرف الحساب المتوقع. ترفض الواجهة الخلفية إعادة إرسال بيانات حساب قديم تحت جلسة حساب جديد. يظل المعرف شرط تطابق فقط، ولا يمنح صلاحية.
4. **سلامة إقرار الحفظ:** الرد التالف أو غير المفهوم أو الذي لا يؤكد نجاح العملية لا يُعامل كنجاح، ولا تُحذف بسببه العملية من قائمة الحفظ المعلّقة. تتوفر أيضًا سلسلة تنفيذ داخل التبويب عند غياب Web Locks.
5. **تصحيح ذاكرة الطلبات:** إشعار التحديث أثناء طلب جارٍ لا يسمح باعتبار النتيجة القديمة حديثة. والقراءة المتأخرة لا تستبدل تحديثًا مؤكدًا في الذاكرة.
6. **العودة من انقطاع الشبكة:** تُسجّل موجة الانقطاع قبل إغلاق المقابس، ثم تحصل مصالحة واحدة عند العودة بدل فقدها أو تكرارها لكل قناة. توجد تغطية لموجتي انقطاع متتاليتين.
7. **أخطاء ومدخلات أوضح:** رفض JSON غير الكائني وبعض مدخلات المصادقة والحالة غير الصحيحة، وتوحيد أخطاء HTTP وإضافة `x-request-id`. أخطاء التنفيذ وقاعدة البيانات تعود 500 برسالة عامة؛ رسائل التحقق المقصودة تبقى 400. لا يسجّل المعالج المركزي نص الاستعلام أو مدخلات المستخدم ضمن رسالة الخطأ.
8. **الحماية المشتركة للطلبات:** فحص المصدر قبل الطفرات، ورفض `Sec-Fetch-Site: cross-site`، وتمرير اتصال Realtime عبر الحماية نفسها. تبقى صلاحيات البيانات وفحص مصدر WebSocket مستقلين في الخادم.
9. **طلبات كبيرة لا تعلق:** إلغاء قراءة طلب تجاوز الحجم لا ينتظر فرع النسخة المخصصة للإشعارات؛ يُلغى الفرع غير المستعمل أيضًا. لا تُنسخ أجسام طلبات الملفات والحالة الكاملة عندما لا يلزم إشعار.
10. **مسار نشر قابل للتتبع:** أمر الإنتاج يتحقق من نظافة checkout، يعيد بناء الإنتاج، يرفض ربط قاعدة/خدمة staging بالإنتاج، وينشر Realtime أولًا ثم التطبيق مع SHA وإصدار PWA والمخطط. أضيف فحص الاعتماديات التشغيلية وحفظ تقرير الاختبار إلى CI، وصُححت أوامر النشر القديمة في التوثيق.

الواجهات الانتقالية الصغيرة التي تعيد تصدير الخدمات مقصودة لحماية حدود الميزات؛ لم تُحذف باعتبارها تكرارًا. اقتصر إزالة التكرار على الحماية المشتركة ومعالجة الأخطاء والتكرار المثبت في الإعدادات.

## أدلة التحقق

الاختبارات الأصلية قبل التعديل: **157 ناجحة**. أضيفت اختبارات سلوكية للأخطاء السابقة واختبار تزامن يعمل على API الحقيقية المبنية وD1 محلية مؤقتة.

نتائج التحقق النهائية لهذه الدفعة:

| الفحص | النتيجة |
| --- | --- |
| مجموعة اختبارات المشروع | 171 ناجحة، دون فشل |
| اختبار API على ملفات النشر المبنية | 49 ناجحة، وهي إعادة تحقق لجزء من المجموعة وليست 49 ميزة إضافية |
| اختبارات قاعدة البيانات | 11 ناجحة |
| TypeScript وlint | ناجحان |
| بناء الإنتاج وstaging ومحاكاة نشرهما | ناجحان، دون نشر فعلي |
| npm audit للاعتماديات التشغيلية | صفر ثغرات معروفة وقت الفحص، وليس ضمانًا ضد ثغرات غير معروفة |
| التزامن المحلي | 100 حساب، 500 طلب مقاس، صفر فشل، وإجابات 100 حساب محفوظة |
| Realtime المحلي | 100 اتصال، والتحقق من وصول الإشعار لكل اتصال |

في تشغيل ملفات النشر المبنية كانت أزمنة الطلبات المحلية: p50 = 1,674 ms وp95 = 3,047 ms وp99 = 3,235 ms. هذا اندفاع متزامن على جهاز التطوير ببيانات اختبار صغيرة؛ ليس زمن استجابة متوقعًا للمستخدمين عبر الإنترنت، ولا قياس تحسن سرعة مقابل نسخة سابقة.

سيناريو التزامن ينشئ **100 حساب اختباري**، ولكل حساب جلسة مستقلة، ثم ينفّذ **500 طلب**: تحميل الجلسة، حفظ الحالة الخاصة، إعادة نفس الحفظ، الإجابة على سؤال مشترك، واستعادة الحالة. يتحقق من بقاء الملاحظات لصاحبها، وحفظ إجابات المئة، وعدم تكرار أثر إعادة الحفظ. ويفتح بالإضافة إليها **100 اتصال WebSocket محلي**، ويتحقق من وصول إشعارات تغيّر الموارد دون محتوى الإجابات. يختبر أيضًا عمليتي كتابة لنفس الحساب من المراجعة نفسها: نجاح واحدة وعودة تعارض للأخرى.

نتيجة التشغيل الآلية في `outputs/saas-local-load.json`، وسجلات الفحص في `outputs/`. لا تحتوي هذه الملفات كلمات مرور أو cookies؛ وهي مستبعدة من Git. يُرفق التقرير آليًا ضمن نتائج CI.

```text
npm test
npm run test:saas
npm run typecheck
npm run lint
python tests/platform-database.test.py
npm audit --omit=dev
npm run cloudflare:check
```

`cloudflare:check` يبني الإنتاج وstaging ويتحقق بمحاكاة النشر `--dry-run`؛ لا ينشر إلى السحابة. اختبار المعدلات ذو الشبكة المشتركة يستخدم binding اختبارية لضمان استقلال مفاتيح الحسابات. اختبار الحمل المحلي ليس قياسًا للمعدلات العالمية أو تكلفة Cloudflare، ولا اختبار تحمل طويلًا لكل الميزات أو لاتصالات WebSocket عبر الإنترنت.

## ما يلزم قبل الإطلاق المدفوع

- حفظ النسخة المراجعة في commit نظيف، ثم نشره على موارد staging المنفصلة واختباره قبل الإنتاج.
- اختبار 100 مستخدم على staging لمدة مناسبة، بمزيج حقيقي من المذاكرة والبطاقات والمراجعة والرفع والاستيراد والاتصالات الحية. تسجيل p95/p99 والأخطاء وCPU وD1 وR2، مع أحجام بيانات تماثل الاستخدام المتوقع. يحدد هذا الاختبار السعة الفعلية؛ لا تُستنتج من عدد الحسابات وحده.
- تجربة المتصفح على سطح المكتب والهاتف وPWA: انقطاع الشبكة، العودة، تبديل الحساب، تسليم الامتحان وتفعيل الاشتراك. اختبارات هذه الدفعة ليست تدقيقًا بصريًا كاملًا.
- التحقق من أسرار الإنتاج وحدود الخطة الفعلية والتنبيهات. إعداد الاستخدام التفصيلي ما زال معطلًا افتراضيًا عبر `QRAFT_TELEMETRY_ENABLED=false`، ويحتاج salt وإعدادات مراقبة صحيحة لتفعيله.
- أخذ نسخة D1 كاملة وتجربة استعادتها في بيئة منفصلة. النسخ اليومية للأسئلة في R2 لا تغني عن استعادة بيانات الحسابات والتقدم من قاعدة البيانات.
- الحالة الشخصية ما زالت مخزنة كـsnapshot بحد سلامة 1,500,000 بايت و5,000 بطاقة وفق القرارات الحالية. التحويل العلائقي التدريجي والاختبارات التاريخية المثبتة بنسخ أسئلة أعمال لاحقة موثقة؛ لم يُدّع تنفيذها بهذه التعديلات.

أمر النشر بعد اجتياز المتطلبات:

```text
npm run deploy:production
```

هذا الأمر ينشر فعليًا عند تشغيله؛ لم يُشغّل ضمن التحقق المحلي. أوامر `deploy:production:realtime` و`deploy:production:app` بقيت متاحة، لكن الأمر الموحّد هو المسار المفضل للترتيب وهوية الإصدار.
