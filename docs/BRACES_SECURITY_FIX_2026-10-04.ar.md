# تصحيح التداخل العميق في braces 3.0.3

الثغرة [GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) ناتجة عن غياب حد عمق شجرة الأقواس. ما زال الإصدار الرسمي 3.0.3 بلا تصحيح منشور وقت التحقق. يناقش المشروع [الإصلاح في PR 72](https://github.com/micromatch/braces/pull/72)، لكن هذا الإصدار لا يعتمد على fork أو commit غير مدمج.

يطبق `scripts/harden-braces.mjs` تصحيحًا محليًا محدودًا على النسخ المثبتة من 3.0.3:

- يحد parser بتداخل 100 مستوى للأقواس المعقوفة والدائرية معًا؛ لا يحتسب الأقواس داخل النصوص المقتبسة أو المهربة أو مجموعات الأحرف كعقد شجرية.
- يحمي compile وexpand وstringify أيضًا من أشجار AST العميقة التي تُمرر مباشرة، ويحمي expand من حلقات parent الدائرية.
- يوقف المدخل العميق بخطأ SyntaxError واضح قبل نفاد المكدس. يبقى دعم الأنماط العادية والنطاقات وخيارات المكتبة كما كان.
- يتحقق من بصمات SHA-256 لملفات المصدر الأصلية الخمسة، أو يعكس التصحيح المثبت ويطابق البصمات قبل اعتماده. يرفض مصدرًا مختلفًا أو إصدارًا غير مراجع، ويفحص الملفات جميعًا قبل الكتابة. يمكن إعادة تشغيله بأمان.

يعمل التصحيح في postinstall مع `npm ci`، ويتحقق منه prebuild وpretest أيضًا. لا يغير رقم إصدار المكتبة ولا يحذف التنبيه أو يخفض إصدارات vinext/shadcn. **قد يظل npm audit يعرض التنبيه لأنه يفحص رقم الإصدار المسجل، ولا يتحقق من التصحيح المحلي.** معالجة السبب مثبتة باختبارات المدخلات العميقة؛ هذا ليس ادعاءً أن قاعدة تنبيهات npm اعتمدت الإصلاح أو أن كل تنبيه للتبعيات انتهى.

شملت الاختبارات إعادة إنتاج فشل المكتبة غير المصححة، ومعالجة آلاف مستويات التداخل بعد الإصلاح، والأقواس الدائرية والمختلطة، وAST الجاهز وparent الدائري، وتوافق glob عبر micromatch، والأنماط المعتادة، ورفض بصمات ملفات غير معروفة دون كتابة جزئية. يثبت checkout نظيف أن `npm ci` يعيد تطبيق التصحيح من ملفات المشروع الملتزمة.

عند توفر إصدار رسمي مصحح: يُراجع ويُحدَّث lockfile، وتُعاد اختبارات الأمن والبناء، ثم يزال سكربت التصحيح وhooks. يبقى اختبار المدخلات العميقة كاختبار انحدار. لا توجد تغييرات في مخطط قاعدة البيانات أو بيانات المستخدمين أو مسارات التطبيق بسبب هذا التصحيح.
