# إدارة Qraft والمراقبة — الإصدار 4.6.0

## النتيجة

صفحة `/Admin` تحتفظ بالإدارة الحالية وتضيف أقسام Monitoring & Usage، وإدارة الموقع والصيانة، والأسعار وتفاصيل الباقات. الإدارة الجديدة تتطلب حساب Superadmin مع MFA مكتمل، ويُعاد التحقق من الصلاحيات في الخادم لكل عملية. بيانات المعاينة المحلية تجريبية ومعزولة عن الإنتاج.

المراقبة تجمع نشاط المستخدمين، ومؤشرات Worker وD1 وR2، والاستعلامات المكلفة عند إتاحتها في الحساب. تعرض Today / 7 days / 30 days، ورسماً يقارن الاتجاهات بمقياسين مستقلين، وجدول القيم الفعلية، وتفاصيل نشاط المستخدم، وحالة Healthy / Attention / Critical مع الأسباب. البيانات غير المتاحة أو القديمة لا تُعرض على أنها صفر أو حالة صحية مؤكدة. الفترات والأيام محسوبة بتوقيت UTC.

## الخصوصية والتكلفة

- Analytics Engine يستقبل عدادات نشاط فقط: إنشاء وإكمال الاختبارات، والإجابات، والأسئلة المستوردة، والبنوك الخاصة، والبطاقات، ومساهمات المراجعة. فتح مساحة المستخدم يُحتسب نشاطاً. هذه قياسات تقريبية لأغراض التشغيل، وليست سجلاً للفوترة أو دليلاً على الأداء التعليمي.
- لا تُرسل نصوص الأسئلة أو الإجابات أو الملاحظات أو البريد أو الاسم إلى Analytics Engine. معرف النشاط HMAC بمعيار SHA-256 وبـsalt سري. تُربط الهوية داخل D1 بجدول صغير عند الحاجة، ويُحذف الرابط مع الحساب. قائمة المستخدمين تُحل عند القراءة؛ الحساب المحذوف يختفي فوراً منها.
- D1 يحتفظ بالإعدادات، وثلاث لقطات مجمعة، وميزانية الاستعلامات اليومية، وروابط الهوية، وسجل العمليات الإدارية. لا يُستخدم كسجل للنقرات. لا تحفظ أسماء المستخدمين في لقطات المراقبة.
- نص الاستعلام من Query Insights يُحوّل إلى بصمة بعد إزالة القيم، ولا يُحفظ أو يُرسل للواجهة كنص SQL. البصمة مفيدة لمقارنة الاستعلامات؛ التشخيص التفصيلي للشيفرة يستخدم أدوات المطور الحالية.
- تفتح الصفحة لقطة مخزنة؛ لا يوجد polling ولا استعلام Cloudflare عند كل زيارة. تحديث يدوي واحد يحجز سبعة طلبات كحد أقصى. الميزانية 60 طلباً يومياً للتطبيق، ومهلة 30 دقيقة لكل فترة، تشمل محاولات التحديث الفاشلة. الاستيراد اليدوي لا يلغي المهلة. تغيير الفترة لا يطلق مزامنة خارجية.
- ميزانية كتابة Telemetry محفوظة في Durable Object القائم: 20,000 نقطة يومياً و500,000 شهرياً، بحجوزات 256 نقطة لكل isolate. الحجوزات غير المستعملة تُفقد لصالح الأمان؛ لذلك قد تتوقف الكتابة عند 19,968 يومياً. توقف المراقبة لا يعطل عمليات المستخدم. تعرض اللوحة الحجوزات واحتمال نقص التغطية.
- نتائج Cloudflare محدودة الحجم والوقت: 12 ثانية لكل طلب، واستجابة أقصاها 1.5MB، و1,000 مستخدم، و20 بصمة استعلام، و31 يوماً. الحد الأعلى يظهر تنبيهاً عند اقتطاع النتائج.
- الاستيراد JSON بحد 100KB، بصيغة `qraft-monitoring-v1`، حتى 31 يوماً و20 بصمة. الاستيراد البديل يقبل بيانات البنية التحتية فقط؛ لا يثبت نشاط مستخدمين مزعوماً. يمكن تنزيل النموذج من اللوحة.

حسب صفحة Cloudflare الرسمية التي روجعت في 27 سبتمبر 2026، تشمل باقة Analytics Engine المجانية 100,000 نقطة كتابة و10,000 استعلام قراءة يومياً. حصة Paid لها حدود مختلفة، والتسعير قد يتغير. الحواجز أعلاه أقل بكثير من الحصة المجانية وتستخدم الخدمات القائمة من دون إضافة خدمة مدفوعة، لكنها لا تضمن مجانية الحساب كله إذا استهلكت تطبيقات أخرى الحصة المشتركة، أو تجاوز استخدام Qraft الأساسي حدود Workers / D1 / R2. لا تتغير حصة البنية الأساسية للموقع بسبب هذه اللوحة، وظهور تنبيه فيها ليس حظراً تلقائياً.

## إعداد الاتصال مرة واحدة

لم يُنشر هذا التحديث، ولم تُضف أسرار حقيقية، ولم يُتحقق من مؤشرات حساب Cloudflare الفعلية.

1. طبّق migration `0025_superadmin_operations.sql` في staging أولاً، ثم تحقق من الترحيلات والبيانات الحالية. لا تحذف قاعدة البيانات أو بيانات الاشتراكات.
2. انشر Worker الخاص بـRealtime قبل Worker التطبيق، لأن حجز ميزانية Telemetry يعتمد على واجهتي `reserveUsageBudget` و`usageBudget` الجديدتين في Durable Object القائم.
3. استخدم Dataset الإنتاج `qraft_usage` وDataset الاختبار `qraft_usage_staging`. ملفات الإعداد تعزل Worker وD1 وR2 وAnalytics؛ التحقق من البناء يمنع خلطها.
4. أنشئ API token بصلاحية Account → Account Analytics → Read للحساب المطلوب فقط، من دون صلاحيات كتابة. خزنه باسم `CLOUDFLARE_ANALYTICS_TOKEN` عبر Cloudflare secrets للـWorker المناسب. لا تضعه في vars أو متغير يبدأ بـ`NEXT_PUBLIC_` أو في ملف مُتعقب.
5. خزّن `TELEMETRY_SALT` عشوائياً، 32 حرفاً على الأقل، كـsecret، وأضف `CLOUDFLARE_ACCOUNT_ID` الخاص بالحساب. لا تغيّر salt دورياً بلا خطة، لأن ذلك يغير معرفات النشاط التاريخية.
6. فعّل `QRAFT_TELEMETRY_ENABLED=true` بعد إعداد الأسرار والتحقق من Dataset وWorker الخاص بـRealtime. الوضع الافتراضي false في الإنتاج وstaging.
7. افتح `/Admin` بحساب MFA، ثم Monitoring & Usage، واضغط Sync Cloudflare. تحقق من بيانات كل مزوّد ومن مصدر اللقطة ووقت تحديثها. الصلاحية والخطة وفترة الاحتفاظ قد تمنع بعض الحقول؛ تظهر هذه القيود صراحة، ويمكن استخدام الاستيراد البديل.

كل استعلام مزوّد محدد في الخادم. الواجهة لا تستقبل token ولا تختار SQL أو GraphQL حراً. لا توجد مزامنة تلقائية أو Cron جديد في هذا الإصدار؛ يوجد مسار جمع محمي يمكن استخدامه لاحقاً، بشرط احترام الميزانية والمهلة نفسيهما وإثبات جدوى التكرار.

CPU المعروض هو أعلى P99 بين مجموعات حالات Worker اليومية، بعد التحويل من microseconds إلى milliseconds؛ ليس P99 موحداً لجميع الطلبات. تخزين R2 هو آخر لقطة متاحة في الفترة، وعمليات R2 إجمالي طلبات وليست تقسيماً كاملاً لفئتي الفوترة. تقارير D1 وQuery Insights مرهونة بإتاحة datasets للحساب. الاحتفاظ الافتراضي لـAnalytics Engine ثلاثة أشهر؛ لا توجد مطالبة بأن القياسات كاملة أو غير مُعاينة.

## الاستخدام غير المعتاد وFair Use

التنبيه الأولي نسبي فقط: يحتاج عينة خمسة مستخدمين على الأقل، وحجم نشاط لا يقل عن 100، وتجاوز ثمانية أضعاف وسيط المجموعة. لا يوقف الحساب ولا يغير الاشتراك ولا يطبق حصة استخدام. يرتبط نشاط المستخدمين بتغطية القياس، وقد يتأثر بالـsampling أو سقف الكتابة. بعد 30–60 يوماً من جمع بيانات Qraft الفعلية، تُراجع توزيعات النشاط ومقابلها من قراءة/كتابة/CPU قبل اعتماد حدود Fair Use. لا يُستخدم هذا التنبيه لإثبات الغش.

## الأسعار والباقات والاشتراكات

إدارة الأسعار تسمح بتغيير اسم ووصف الباقة، والسعر السنوي بالهللة، والمميزات وحدودها القابلة للتنفيذ. Free يبقى بسعر صفر. تتحدث صفحة الاشتراك وعروض السعر والتحقق في الخادم من المصدر نفسه؛ تغيير السعر لا يغير تاريخ انتهاء اشتراك قائم ولا يعيد تسعير حدث مالي قديم.

التغييرات تتطلب سبباً وتسجل في Audit. الحدود الهندسية تمنع نشر سعات لا يستطيع التنفيذ الحالي حمايتها. حدود أكبر موجودة سابقاً، ومنها Unlimited، تبقى إذا لم تُعدّل؛ لا يسمح برفعها من هذه الواجهة فوق السقف الهندسي. خفض حدود الباقة لا يحذف المحتوى القائم؛ تُطبق الحدود عند العمليات الجديدة. لا تُقبل حدود يرسلها المستخدم في ملفه الشخصي بديلاً عن سياسة الخادم.

تمديد الاشتراك يدعم 1–730 يوماً مع معاينة تاريخ الانتهاء. الإهداء يدعم عدد أيام محدداً 1–730، مع حفظ التوافق مع المكافآت القديمة الشهرية والسنوية. حظر الحساب المؤقت يدعم 1–365 يوماً، ويُرفع تلقائياً عند الانتهاء. الحظر الدائم الحالي وقوائم الحظر تبقى متاحة؛ الحساب Superadmin محمي من الحظر بهذه العملية. كل تغييرات الوصول تُنشر عبر آلية تحديث الحساب الحالية.

## الصيانة

إدارة الموقع تتيح رسالة الصيانة، وموعد انتهاء اختياري خلال سبعة أيام، وتفعيل الصيانة أو إعادة الفتح. حفظ الإعداد يستخدم رقم مراجعة لمنع الكتابة فوق تعديل متزامن، ويسجل السبب والتغيير. الزائر يتلقى صفحة صيانة بحالة HTTP 503؛ واجهات API تتلقى JSON 503 وRetry-After. المشرف المتحقق يستطيع متابعة الإدارة والتراجع. تبقى خطوات الدخول وMFA متاحة للاستعادة. الصيانة توقف الطلبات المتصلة؛ محتوى PWA المخزن على جهاز غير متصل قد يبقى ظاهراً حتى الاتصال.

## التحقق

- 156 اختباراً في مجموعة المشروع، تشمل 16 اختباراً موجهاً للإدارة والمراقبة واختبار خصوصية وسقف القياس المتزامن.
- 46 اختباراً لواجهات الخادم على حزمة staging النهائية، و11 اختباراً لقاعدة البيانات والترحيلات.
- فحص الأنواع وجودة الكود وبناء staging وفحص حزم التطبيق وRealtime بوضع dry-run.
- تحقق محلي من واجهة الإدارة ببيانات وحسابات تجريبية معزولة، على عرض 390 و1028 و1440 نقطة، من دون تمدد أفقي للصفحة. تم فتح نافذة النشاط وتحرير تفاصيل الباقة ومعاينة تمديد الاشتراك، وتفعيل الصيانة والتحقق من صفحة الزائر ثم إعادة الفتح بنجاح. لا تُستخدم النتائج التجريبية كبيانات تشغيل حقيقية.
