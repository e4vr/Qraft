## التغييرات التي تحافظ على الصحة

- فهارس مراجع الأسئلة والتاريخ وروابط المشاركة القديمة تمنع المسح المتكرر أثناء الحذف. بقي الحذف وعلامته والتدقيق والتقاعد وتنظيف المراجع في معاملة واحدة.
- إنشاء البنك يقرأ ملفات الحسابات المطلوبة للعملية فقط. عمليات التحكم العام تحتفظ بالسياق المطلوب، وإدارة الحسابات تقرأ ملفاتها المستهدفة كاملة.
- البحث يستخدم ترتيب FTS عبر `rank` المكافئ افتراضيًا لـBM25، بنفس حد 1,000 مرشح لكل بحث. يقارن الاختبار النتائج وترتيبها على D1 محلي، بما فيها التعادل وأعداد تتجاوز الحد.
- مفاتيح SHA-256 للنص والمحتوى مشتقة وفق التطبيع السابق ومفهرسة داخل البنك. البصمة تحدد المرشحين؛ المقارنة الأصلية للنص والخيارات والإجابة الصحيحة تبقى شرط التخطي.
- SQL يبطل المفاتيح بعد تحرير هوية السؤال أو تغيير الحالة/البنك أو الحذف مهما كان الكاتب. تعديل التصنيف أو المصدر أو الشرح وحده يحتفظ بمفاتيح الهوية ويحدث إصدار البحث، لمنع عرض حمولة قديمة.
- كاش Worker محدود بالحساب والبنك والاستعلام وإصدار الكاشف وإصدار SQL لمحتوى البحث. الإصدار عالمي لأن BM25 يعتمد على إحصاءات جميع المحتوى. أي تغيير محتوى يمنع إعادة استخدام الفحص السابق؛ تعذّر الكاش يعود للبحث المعتاد.
- إصدار الفحص يُتحقق منه داخل معاملة الحفظ. التعارض يتراجع عن بيانات الدفعة ويعيد فحصها حتى محاولتين إضافيتين مع requestId نفسه. بقيت المسودة والاستئناف والحفظ الجزئي الآمن.
- سجل SQL متزايد يثبت الإضافات والتعديلات والحذف داخل معاملة الكاتب، بما فيها الإجراءات المتسلسلة والاستعادة. الجلب الجزئي يستخدم مفاتيح السجلات وسياسة التفويض نفسها المستخدمة في اللقطة الكاملة.
- إضافة أو حذف أو تغيير ظهور بنك يمكن أن يعيد لقطة البنك المتأثر فقط. تُزال بياناته السابقة قبل تطبيق النسخة المخوّلة الحالية، وتبقى بيانات البنوك الأخرى. تغيّر صلاحيات لا يثبت السجل نطاقه بأمان يستعيد اللقطة الكاملة.
- تُحفظ اللقطة المؤكدة وموضعها في عملية IndexedDB واحدة منفصلة عن المسودات. فشل التخزين لا يقدّم الموضع. الأحداث المكررة، إعادة الاتصال، تغيير الحساب والموضع القديم تُعالج دون polling دوري.
- التنظيف اليومي يحتفظ بآخر 50,000 تغيير على الأقل. الموضع الأقدم أو نافذة تتجاوز 2,000 تغيير تستعيد لقطة كاملة. الرقم المتزايد لا يُعاد استخدامه بعد التنظيف، وفحص الاحتفاظ وقراءة النافذة يحصلان في دفعة واحدة.
- المقترحات تصل للمؤلف والمراجعين المخوّلين؛ التصنيف يصل لمشاهدي البنك إذا تغير. الجلسات القديمة تحتفظ بإشعاراتها حتى تتصل بالبروتوكول الجديد. دفعة متخطاة بالكامل تحدث تقدم الملف والتدقيق فقط؛ الطلب المؤكد المكرر لا يعيد الإشعارات.

زيادة الكتابات هي كلفة الفهرسة وسجل الاستدراك والتحقق الذري؛ لم نعوضها بتأخير التحديثات أو تعطيل حفظ بيانات. مفاتيح قديمة ناقصة تستخدم FTS، فلا تعتمد الصحة على اكتمال التعبئة.

## التحقق وإعادة القياس

اختبارات API تقارن الجلب الجزئي باللقطة الكاملة بعد تعديل سؤال وحذفه، وإضافة بنك وحذفه وتحويله بين العام والخاص وسحب العضوية. تشمل خصوصية المقترحات، قنوات المراجعة والجلسات القديمة، المسودات، عزل الحسابات، فشل التخزين وانتهاء الاحتفاظ. اختبار استيرادين متزامنين مع التخطي الاختياري يتحقق من حفظ نسخة واحدة واستدراك التعارض.

اختبارات 0.5/5 mg، النفي، اختلاف الإجابة وإعادة ترتيب الخيارات، وإبطال الكاش، والتراجع عن بيانات المعاملة والفهرس وسجل التغيير تحمي السلوك الحالي. تشمل الفحوص اختبارات المشروع، البناء، الأنواع والجودة، المخطط ومجزئ الترحيلات ومجموعتي Python.

أدوات إعادة القياس المحلية:

```text
node scripts/benchmark-qbank-reads.mjs
node scripts/benchmark-qbank-reads.mjs --import
node scripts/benchmark-qbank-deletion.mjs
```

تنشئ قواعد اختبار مؤقتة ولا تتصل بقاعدة الإنتاج. تحفظ تفاصيل الاستعلامات والأرقام في `outputs/`.

## تشغيل الإصدار لاحقًا

1. إنشاء commit وبناء نظيف منه، ومراجعة النسخة الاحتياطية والمخطط المستهدف.
2. تطبيق 0030–0032 واختبار الإصدار على staging قبل الإنتاج. ترحيلات الإنتاج والنشر يحتاجان طلبًا صريحًا وفق دستور المشروع.
3. نشر Worker القنوات الحية قبل التطبيق. التطبيق يحتفظ بمسار إشعار البنك السابق إذا كان Worker القنوات أقدم.
4. تعبئة مفاتيح الأسئلة القديمة تدريجيًا عبر POST الإداري `import-search-reindex`: البداية `{}`، ثم إعادة `collection` و`cursor` اللذين يرجعهما الخادم حتى `done=true`. كل طلب يقرأ حتى 200 سجل عبر فهرس النوع/المعرف، ويشترط بقاء حمولة السجل كما قُرئت قبل كتابة المفتاح.
5. قياس القراءات والكتابات والوقت وCPU على staging؛ القياس المحلي لا يعوض ذلك. هذه التعديلات لا تعيد الحصة اليومية المستنفدة إلى حساب D1.

يمكن الرجوع إلى التطبيق السابق مع إبقاء هذه الترحيلات الإضافية؛ يعود إلى تحميله الكامل ويستمر SQL في سجل التغييرات. لا يلزم حذف جداول أو بيانات أثناء الرجوع.
